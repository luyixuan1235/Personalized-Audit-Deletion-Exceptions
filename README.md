# Exception Erasure

Replication package for **Auditing Exception Erasure in Personalized Permission Prediction** (double-anonymous submission).

This repository reproduces the tables and analyses in the manuscript, including an end-to-end rerun of the publicly released permission-prediction system of Wu et al. (IEEE S&P 2026) from *their* code on *their* data.

No author names, affiliations, or personal URLs are included in this package.

---

## Double-anonymous review

1. Push this repository to **GitHub as a private repo** (do not make it public during review).
2. Wrap that private repo with [Anonymous GitHub](https://anonymous.4open.science/) so reviewers see anonymized commits and no account names.
3. Put the Anonymous GitHub URL in the manuscript. Do **not** put a `github.com/<your-username>/...` link in the paper until after acceptance.

What *not* to upload: `.venv/`, `wu-repo/`, `.env`, API keys, or any file with your name.

## Quick start

```bash
bash setup.sh              # our experiments (PyTorch CPU wheel)
bash run_paper.sh          # regenerate analyses on both corpora
```

Smoke test (few epochs; **numbers will be wrong**; only checks that scripts start):

```bash
PERM_QUICK=1 bash run_paper.sh
```

Optional: also clone and rerun the released Wu et al. artifact.

```bash
bash setup.sh --wu
echo "OPENAI_API_KEY=<your key>" > wu-repo/.env   # only if you want to re-query the LLM
bash run_paper.sh --wu
```

LLM **prediction caches are shipped**. Reviewers can reproduce the reported analyses without an API key. A live LLM rerun is optional and costs a few dollars.

## What is in this package

| Path | Contents |
|---|---|
| `data/` | Wu corpus, converted to `(user, domain, tool, data type) → {grant, deny}` |
| `data_spa/` | SPA corpus, same schema |
| `src/` | models, metrics, and experiment scripts |
| `results/`, `results_spa/` | archived JSON used by the paper |
| `requirements.txt` | supported version ranges |
| `requirements-lock.txt` | exact versions of the audited rerun |
| `setup.sh` | creates virtualenvs |
| `run_paper.sh` | regenerates every reported table (blocks R1–R17) |

`wu-repo/` is **not** shipped. `setup.sh --wu` clones [Wu et al.'s public artifact](https://github.com/llm-platform-security/ai-agent-permissions) into that directory.

Two virtualenvs are required on purpose: this code uses PyTorch; the released artifact uses TensorFlow + `recommenders==1.2.1` pinned to `numpy<2`. They do not coexist in one environment. The `--wu` environment needs about 2.5 GB free.

| File | What it is |
|---|---|
| `results/table_eor_train_majority.json` | train-only majority EOR, denominators, cluster CIs |
| `results/table53_eor_deployed.json` | deployed CF / IC / hybrid EOR |
| `results/table21_peruser.json` | per-user FPR and count-weighted concentration |
| `results/table24_denial_ablation.json` | denial-representation ladder |
| `results/table_eight_repairs_audit.json` | committed repair cells vs own baselines |
| `results/table33_decision_layer.json` | exception-aware permission guard |
| `results/table_llm_response_audit.json` | LLM cache completeness (98.8–100% parsed) |
| `results_spa/` | SPA counterparts |

Every number quoted in the paper is regenerated by one `run_paper.sh` block. Block IDs (R1–R17) are commented in that script.

Manuscript figures are produced by `src/experiments/generate_paper_figures.py` when a sibling `journal-manuscript/` directory is present. They are not required to check the JSON tables.

## Protocol (read before quoting a number)

- Evaluate each model at the **deployed threshold** (equal-error point fitted on the *training* fold), never at a fixed `p = 0.5`, except in `run_posthoc.py` where calibration makes `0.5` meaningful.
- Per-user thresholds and calibrators are fitted on **held-out** data. Oracle fits on test labels are labeled as such and are not quoted as results.
- Concentration uses a **count-weighted** false-grant share vs a count-weighted permutation null.
- All cells share the same per-user folds (seed 42).
